# dsh-tool-policy-shell

[English](README.md) | 中文

此 effect 作用域提供者通过现有 `ctx.toolPolicy` 服务解释显式映射的 shell 工具。它组合固定安全检查、有序部署规则、保守解析的只读集合，以及有界且独立的意图与命令效果复核。Bash 与 PowerShell 都由配置支持；工具名和参数名都不是内置默认值。

## 配置与行为

`mappings` 指定支持的工具、命令参数和可选的执行模型意图参数。`intent`、`primary` 与 `secondary` 选择三个不同的 `ctx.llm` 提供者和模型路由。每条路由都可以设置提供方中立的 `reasoningEffort`，该值会原样传给 `ctx.llm`；省略时保留该模型路由的默认推理行为。超时、输入输出界限、摘要和原因上限、效果数量以及有序命令规则都必须配置。运行时会排除与执行模型相同的路由；缺少独立证据时失败关闭。

主机根目录破坏原语和受保护凭据路径在规则或模型调用前被拒绝。无条件 Git 强制推送、远端删除和镜像操作需要询问；`--force-with-lease` 与 `--force-if-includes` 继续接受普通求值。规则对整条命令做类 glob 匹配，最后一个匹配生效，且 allow 规则不能放行包含 shell 元字符的命令。

解析快速路径只接受写入标准输出的字面量只读流水线，且解析后的文件必须位于工作区或平台临时目录。替换、重定向、执行元字符、写入选项、无法解析的路径和符号链接逃逸都会离开快速路径。

对于未匹配命令，意图路由只接收有界的直接用户意图和执行模型意图；主效果路由只接收完整有界的命令和工作目录。二者以零温度、各自配置的推理强度和严格 JSON 格式并发运行。解析器接受裸 JSON 对象或一个覆盖完整响应且标记为 `json` 的 Markdown 代码围栏；附加说明、多个内容块和畸形 JSON 仍然无效。模型输出先按封闭效果词汇验证，再由宿主代码推导裁决。读取工作目录之外的文件系统状态需要对齐且明确的 `outside-workspace-read` 意图；`host-read` 仅指非文件形式的操作系统或硬件信息，凭据访问仍单独要求审批。只有主路由没有返回有效效果证据时才运行次效果路由；它绝不会覆盖已验证的敏感效果。无效、不可用、失败、超时、冲突或词汇外证据都变为 `ask`；调用方取消仍是取消。

## 安全行为

诊断只保留有界且清理过的摘要、原因和封闭效果。原始用户文本和命令参数保留在既有 `user/message` 与 `tool/call` 事件中。分类请求事件记录路由、提示词、选择器和界限，因此无需复制任一原始输入即可重建请求。

## 模型体验

### 条件授权反馈

#### 模型看到什么

提供者不添加主提示词。执行消费者根据 `tools/pre-execute` 裁决呈现拒绝或审批反馈。

#### Token 影响

确定的固定、规则和解析只读情况不消耗分类 token。其他调用消耗两个并发辅助请求；主效果证据缺失或无效时再消耗一次请求。墙钟时间通常取意图路由与主效果路由中较慢者，而不是二者之和。

#### KV 缓存影响

分类请求使用固定系统前缀和稳定 JSON 字段顺序，有利于辅助缓存复用，且不修改主对话前缀。

## 已知限制和延后工作

- 快速路径刻意只识别小型 shell 语法；其余命令使用独立模型证据。
- 命令超过配置界限时会询问，不会把截断命令交给分类器。
