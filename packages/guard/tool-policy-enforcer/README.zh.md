# dsh-tool-policy-enforcer

[English](README.md) | 中文

此消费者在 `tools/pre-execute` 上执行 `ctx.toolPolicy`。不支持和允许的工具调用 `next()`；拒绝会短路执行。`ask` 裁决立即进入现有审批流水线，因此 `ctx.approval` 仍是人工决定及其持久审计的唯一所有者。

`enforceWhen` 可选择将评估限制为实际 `sandbox/mode` 与 `approval/policy` 值的合取条件。执行器在咨询任何提供方之前，从调用会话的持久事件中折叠这些值。省略条件会保留无条件执行；缺少已配置的值时仍会执行，因为会话无法据此确认已配置的绕过条件。

## 直接审批

执行器无状态，也没有重试阈值。每个提供者意见和最终结果都记录为 `tool-policy/decision`，包含有界风险、类别和原因，但不复制原始参数。策略失败变为 `ask`；调用方取消会重新抛出并保持为取消。确定性的提供者拒绝绝不会进入审批。

## 模型体验

### 条件工具结果

#### 模型看到什么

第一次 `ask` 就会打开现有人工审批流程。批准只执行该精确调用一次；拒绝、取消或没有可用应答器时，返回审批服务的有界工具错误。拒绝使用提供者的有界原因且不提示。

#### Token 影响

不满足 `enforceWhen` 的调用、允许的调用和不支持的调用不添加模型可见 token。拒绝或延迟的调用在下一请求中添加一条短工具结果。

#### KV 缓存影响

策略反馈追加在现有对话前缀之后，不会使先前 KV 缓存条目失效。

## 已知限制和延后工作

- 没有代理的工具调用会继续委托，因为不存在会话或人工审批路由。
