# Agent Note: 已配置模型的 catalog 继承

Status: implemented

[English](2026-08-17-configured-model-catalog-inheritance.md) | 中文

## 问题

当已配置模型的请求标识与 pi-ai 已安装 catalog 标识不完全一致时，该模型会被物化为手工声明模型。它保留已配置标识与路由默认值，却静默丢失已安装的推理档位、兼容行为、请求头、输入模态、定价及其他请求元数据。因此，带日期的标识和提供方路由后缀会表现得不同于它们有意代表的 catalog 模型。

## 决策

一个 `models` 条目可以通过 `catalogModel` 指定同一提供方路由上的已安装模型。解析器会完整展开该来源模型，再应用已配置条目，同时继续把条目的 `id` 作为发送给提供方的标识。已配置的容量、推理档位、兼容开关与其他受支持字段仍然优先于继承值。

显式来源是一项断言，而不是提示。空来源或已安装路由 catalog 中不存在的来源会使 profile 解析失败，诊断中会点名提供方、已配置模型与无效来源。图形模型编辑器在修改可见字段时会保留自身未公开的字段，包括 `catalogModel`。

## 备选方案

**在每个带路由后缀的标识上重复推理与兼容字段。** 否决，因为这只会复制今天已知的元数据，会在 pi-ai 修正模型后产生漂移，并且仍会丢失未建模字段或未来新增字段。

**通过移除标识中的日期或路由后缀来推断来源。** 否决，因为提供方模型标识是不透明字符串。拼写约定不能确立语义等价关系，而错误推断会静默改变请求行为。

**接受未知来源并回退为手工声明模型。** 否决，因为显式字段表示必须继承该行为。缺少来源时继续运行，会让原始故障隐藏在看似更精确的配置下。

## 影响

部署可以在协议请求中保留精确的带日期或路由后缀标识，同时继承已安装模型的完整请求行为。来源必须属于同一提供方路由，因此不能把元数据跨凭据或端点带入。

已安装 catalog 升级后，可以在无需修改 Harness 代码的情况下为继承模型增加元数据。显式字段仍是稳定覆盖，无效来源名称会在任何提供方请求发出前失败。
