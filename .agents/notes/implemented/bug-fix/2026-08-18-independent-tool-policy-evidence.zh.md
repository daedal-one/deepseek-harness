# Agent Note: 独立工具策略证据与直接审批

Status: implemented

[English](2026-08-18-independent-tool-policy-evidence.md) | 中文

## 问题

shell 策略曾把原始用户请求、执行模型描述、命令和工作目录一起发送给单个效果分类器。因此，宽泛的用户请求会改变同一条只读命令的分类方式：简单的 `cat`、`sed` 和 `awk` 诊断会从周围任务继承整个仓库的修改或删除风险。分类器随后还把自身解释当作策略决定，使宿主代码无法验证的自由形式类别和风险阈值承担了授权语义。

确定性只读集合太小，无法覆盖常见检查流水线。误报的 `ask` 还会强制执行模型重复完全相同的调用，之后才会咨询现有审批服务。这次重复增加了一个模型轮次，却没有增加独立证据或人工决定。

## 决策

`dsh-tool-policy-shell` 仍是现有 `ctx.toolPolicy` Service Definition 的 effect 作用域提供者。`dsh-tool-policy-enforcer` 仍是其普通 `tools/pre-execute` Consumer。意图和效果复核器是 shell 提供者内部传递的私有实现能力；它们不会为单个内部调用方创建公共服务，agent loop 也保持不变。

固定安全决定和有序部署规则最先运行。随后，一个刻意精简的解析器放行只写入标准输出的字面量只读流水线，且解析后的文件操作数必须位于工作区或平台临时目录。替换、重定向、执行元字符、写入选项、无法解析的操作数和符号链接逃逸都会离开此快速路径。解析器之外的命令继续接受模型复核；解析器不完整绝不会授予权限。

未匹配命令产生两个独立请求。意图路由接收有界的直接用户文本和执行模型陈述的意图，但不接收命令。主效果路由接收完整有界的命令和工作目录，但不接收用户或执行模型意图。二者并发运行。配置要求意图、主效果和次效果三个不同路由；运行时排除与执行模型相同的效果路由。若意图路由与执行模型相同，则因自我复核不独立而失败关闭。

辅助输出使用封闭的 shell 效果词汇。严格解析器拒绝额外字段、未知效果、非法风险值、允许与禁止集合冲突，以及超出部署界限的输出。意图复核器报告对齐关系以及用户允许或禁止的效果；效果复核器只报告命令的直接效果。确定性宿主代码组合已验证证据：基础读取和本地计算可以通过，工作区修改和工作目录之外的普通文件系统读取要求意图对齐且类别明确匹配，网络、凭据、进程控制、特权、外部修改或破坏效果则需要审批。`host-read` 仅限非文件形式的操作系统或硬件信息，因此不能授予更具体的 `outside-workspace-read` 效果。模型提供证据，不拥有最终策略规则。

意图请求和主效果请求共享完全相同的在途输入，墙钟时间通常取较慢路由，而不是二者之和。只有主路由没有返回有效效果证据时才运行次效果路由；它绝不会覆盖已验证的敏感效果。被替代的格式错误或不可用主意见仍保留在审计中，但不会抬高已验证次决定的风险。调用方取消会释放其等待者；没有等待者时取消共享工作。

分类请求事件在调用前存储路由、用途、固定系统提示词、重建选择器和输入界限。原始用户文本保留在 `user/message`，原始工具参数保留在 `tool/call`。不变量验证当前开放轮次、匹配调用、用途与输入选择器一致，以及任何被引用的直接用户消息。这样无需保留第二份原始副本即可精确重建。

最终 `ask` 会立即进入现有审批服务。执行器没有重试阈值或进程内机会状态。批准只对该精确调用生效一次；确定性拒绝绝不会变为可审批。

## 曾考虑的替代方案

**保留单个分类器并调整提示词。** 被否决，因为同一模型仍会同时接收授权上下文和命令效果；提示词可以劝阻污染，却无法使证据独立。它还会继续让自由形式模型类别控制决定。

**发布单独的意图复核 Service Definition。** 被否决，因为只有 shell 策略提供者消费这份解释。私有能力闭包可保留插件边界，而不增加不完整的公共接缝或预设的提供者生态。

**为只读快速路径采用 Tree-sitter Bash。** 对此有界语法而言被否决。Node 绑定会增加原生构建和平台打包工作，而 AST 仍需要仓库自有的选项、重定向、解析路径和符号链接逃逸语义规则。失败关闭的字面量解析器保持更小的授权面，并有直接的非法用例测试。将来若需要更广语法，可以再证明引入维护中解析器依赖的价值。

**让复核器返回开放式效果。** 被否决，因为同义词和自造类别会使宿主策略含糊，并重现原先由模型拥有阈值的问题。封闭列表需要维护类别，但让每个已接受结果都能由确定性代码执行。

**在审批前保留精确调用重试。** 被否决，因为重复相同参数不会增加证据，却会在误报时制造模型可见阻力，并重复 `ctx.approval` 已经拥有的一次性职责。

## 后果

常见字面量检查流水线完全避免辅助延迟。其他命令通常发出两个小型并发请求，而不是一个混合请求；主效果证据缺失或无效时可发出第三个请求。额外 token 换来独立证据，并受固定提示词、封闭 JSON、共享在途请求和按需次路由约束。

随着新 shell 能力出现，封闭效果词汇可能需要有意识地扩展。未知效果失败关闭，因此遗漏类别会触发审批而非授权。只读解析器同样偏向误拒：不支持的选项或语法会使用模型证据，而不是靠猜测扩张确定性授权面。

误报的 `ask` 现在会在第一次调用时到达人。分类器不确定时，这可能显示更多审批提示，但它移除了强制重试轮次，并让现有持久审批审计继续作为唯一人工决定机制。

聚焦单元测试覆盖严格证据解析、宿主组合规则、只读流水线逃逸、并发与共享调用、路由独立性、回退、超时、取消和卸载。真实 Loader 组合覆盖完整提供者与消费者生命周期，无密钥 Daedal 快照通过独立意图和效果路由驱动组装后的 profile。一个可自行跳过的真实提供方测试在平台临时目录下使用固定合成输入，区分本地检查与需要审批的网络访问，且不披露仓库内容。
