# Agent Note: 缓冲式英文输出 guard

Status: implemented

[English](2026-08-16-buffered-english-output-guard.md) | 中文

## 问题

编程 agent（智能体）使用的一些精确模型路由即使在 persona 中要求英文，也可能用中文输出说明文本或推理。仅靠提示词无法执行面向用户的语言要求。改写已经记录的助手消息会使持久历史与 UI 显示及模型后续派生的文本产生分歧。翻译还会处理不可信模型输出，因此不得暴露凭据、重新解释工具参数，或静默破坏代码和标识符。

## 决策

`@deepseek-ai/dsh-english-output-guard` 是使用现有扩展点的指定范围函数插件。它注册一个英文策略段落和一个 `llm/stream` waterfall（瀑布式事件）包装层。该包装层只选择由进程标记的 agent loop（智能体循环）请求，并要求其精确提供方和模型出现在必填配置中；辅助请求和非目标请求会立即委派。

包装层只缓冲目标流。错误和已中止结束会精确回放。成功流通过 `BlockAssembler` 组装；没有大量未保护汉字的响应会逐字节回放原始分片和 replay 状态。偏移会触发一次辅助 `ctx.llm` 请求，并受显式路由、token 上限、输入上限和截止时间控制。私有请求身份防止递归拦截，插件 dispose（资源释放）会中止并等待其拥有的翻译工作。

只有文本和推理块会被翻译。代码围栏、行内代码、链接目标、URL、路径、标志以及类似标识符的片段会变成无冲突占位符。结果必须是严格 JSON，包含精确的所选索引和类型、非空翻译、各占位符恰好一次，并且没有大量未保护汉字。工具调用名称、id、原始 JSON 参数、块顺序、token 用量和结束原因保持不变。发生转换的响应使用一条合成规范分片流并省略提供方 replay 状态；没有变化或选择保留的响应会保留精确原始流。

辅助分发前，`english-output/translation-request` 会在发起请求的打开步骤内记录精确翻译输入和受影响的原始块。`english-output/translation-result` 会记录 `translated`、`blocked` 或 `preserved` 结算及受限失败信息。这些事件仅用于日志；只有接受后的分片和助手消息进入规范 UI 与模型历史。不变量配套插件会把每个请求和结果关联到打开步骤，并在轮次没有中止时，把 `translated` 和 `blocked` 结算关联到后续规范助手消息。

## 验证

包测试通过真实 AgentLoop 覆盖汉字阈值、受保护片段、精确路由选择、带 replay 状态的无偏移回放、文本和推理翻译、代码/路径/URL 保留、结构化工具调用保留、token 用量和结束原因保留、无效输出、提供方失败、超时以及两种失败模式。该包作为独立 TypeScript 项目通过类型检查。交付组合快照仍由挂载 guard 的组合包拥有。

## 备选方案

**仅使用提示词执行。**不予采纳，因为提示词表达了偏好，但不能防止模型偏移进入持久助手历史。

**事后助手消息变更或替换事件。**不予采纳，因为流包装层可以在追加规范分片和消息事件前做出决定。第二种修正机制会在没有当前需求的情况下扩大会话投影、持久化、回放和每个 UI 消费方。

**直接使用提供方 HTTP。**不予采纳，因为这会绕过适配器路由、凭据、取消规范化、遥测、提供方归属和测试适配器。辅助工作使用 `ctx.llm`。

**翻译工具参数和结构化块。**不予采纳，因为翻译可能破坏可执行 JSON、调用身份、路径和提供方协议。只有文本块进入翻译模型。

**修改 agent loop。**不予采纳，因为 `llm/stream` 已经拥有日志记录前的流拦截，而 `isAgentLoopRequest` 能区分精确的主调用对象。loop 不需要感知这项部署策略。

## 后果

目标偏移以流式延迟换取单一规范历史：可见输出会等待主响应结束和辅助翻译。无偏移成功、错误、已中止、非 loop 以及非目标流会保留原始字节，而且不进行辅助请求。翻译失败时，部署必须明确选择保留原始响应或隐藏受影响文本。持久审计可以重建每项模型可见辅助输入，而不会存储提供方凭据或第二份助手历史。
