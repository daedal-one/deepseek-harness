# Agent Note: 持久化审阅记忆

Status: implemented

[English](2026-08-16-durable-reviewed-memory.md) | 中文

## 问题

会话记录保存已发生的内容，但不能提供有界、可查询的持久项目知识。若自动把提取文本视为事实，猜测、过期信息、工具输出中的指令或执行模型声称的角色都可能获得长期权限。全局记忆还跨越项目隔离，因此每次变更都需要明确的人类同意。

## 决策

记忆是完整的能力接缝。`dsh-memory` 负责显式项目/全局作用域、品牌化标识符、比较并交换修订、证据、可信度、时间有效期、矛盾链接和 Provider 选择。`dsh-memory-sqlite` 负责应用标识的单调 schema、事务生命周期转换、保守保留策略和有界作用域内搜索。普通工具提供查询、读取、提案、质疑和检查点；每次全局写入都在执行时请求批准，并且只在 `allowed-once` 时继续。

待处理项发现、审阅、取代和删除由独立工具提供。它们依据配置所选、持久化在 `subagent/descriptor` 中的 principal 授权，而不是模型参数、persona 文本或角色标签。每次执行都会检查授权。全局审阅者变更仍保留同样的一次性批准要求。

提取器观察已完成的 `turn/end`，等待会话持久化刷新，然后进入有界队列。它在调度前记录并刷新精确辅助请求，随后记录组装响应、结束状态、用量、提案标识符和有界失败。提取事实是项目作用域提案；审阅前不会生效。队列饱和、格式错误、超时、取消和 Provider 失败都不会使父级轮次失败。卸载会中止并等待活动工作。

## 考虑过的替代方案

**把提取事实直接注入提示词。** 拒绝，因为模型可见状态会缺少持久审阅生命周期，过期或矛盾声明可能静默覆盖当前证据。

**通过角色工具参数或 persona 授权审阅者。** 拒绝，因为两者都是模型可控文本。持久、由进程拥有的 subagent principal 才是授权事实。

**把会话日志用作查询数据库。** 拒绝，因为项目/全局隔离、审阅转换、保留策略、时间过滤和跨会话查询会在各 Consumer 中重复，并把记忆 schema 演进耦合到会话记录持久化。

## 后果

持久事实保留证据并可审阅，项目边界明确，全局状态没有实时批准就不能改变。检索只把所选记录加入模型上下文。提取在父级轮次后增加有界辅助延迟，而 Provider 失败不会破坏已完成轮次。搜索目前基于子串；当语料测量证明需要排序基础设施时，可在 Provider 接口后替换。
